# Home-care cinematic site

1. Load Caveman first from `references/skill-routing.md`. Keep updates concise; keep deliverables complete.
2. Inspect the existing site and owner facts. Never inherit another agency's services, logo, founder, voice, licenses, calendar, keys, testimonials or contact data.
3. Copy `assets/starter` for a lightweight configurable starting point. The production Astonishing Touch implementation is preserved separately in its git history; this starter is intentionally unbranded. React motion source is included in `assets/react-motion` for adaptation.
4. Set agency identity and enable only confirmed services in `agency.json`. The same enabled service list must drive navigation, sections, structured data, FAQs and receptionist knowledge. Optional services are off until confirmed. Distinguish nonmedical reminders from medication administration and skilled care.
5. Read `references/skill-routing.md`; load only skills relevant to the current phase. Use the smallest motion stack that achieves the brief. Preserve native scrolling, mobile action visibility and reduced-motion support.
6. Read `references/cinematic-prompt.json` before media generation. Create and inspect the first image, then animate it. Keep professional camera/lens/light/meta guidance explicit. Gear and tokens are offscreen instructions, not scene objects or guaranteed technical output properties. Confirm available model capabilities before submitting jobs.
7. Read `references/service-storyboards.md` and match each service to a visibly completed action. Use multiple angles when they clarify actions. Reject near-static gestures, duplicate clips and mismatched services. Maintain an asset/job ledger and never blindly resubmit pending jobs.
8. Wire receptionist, booking and inquiries to this agency's own server-side credentials and destinations. Use a friendly natural voice selected by the owner, identify AI honestly, ground answers in approved facts, hand prices to staff, and retrieve current facts when needed. Do not claim a booking without a successful scheduler response.
9. Run the starter validator, build the final application and inspect desktop/mobile/reduced motion. Watch each clip and loop seam; verify actual actions, logos, English text, no sound and unique files. Test inquiry receipt and agent tools. Report untested integrations plainly.
10. Preserve access settings. Public indexing requires a deliberate public launch. No ranking guarantees. Save source to git and record published version plus outstanding owner dependencies.

The starter supplies presentation/configuration, not a working voice or booking backend. Integrate those before describing them as available. Never copy production secrets into the template.
