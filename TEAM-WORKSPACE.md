# Astonishing Touch team workspace

Implemented routes: `/team` (real sign-in, disabled until connected), `/team/activate` (staff invitation), `/team/demo` (fictional in-memory review, returns 404 on Vercel production). The public site's visual design remains separate from this pearl-glass workspace.

Managers can create/edit client names or approved identifiers, phone numbers, home addresses, verified coordinates and a 50–1000 meter clock area; manage staff contact details and SMS opt-in; upload private employee/client photos; assign staff, schedule visits, review clock readings, correct times with reasons, and export the most recent 500 visits plus every open visit. Owners can also change other staff members' roles and deactivate access. Employees see only their own records and assigned active clients. No clinical charts, wages, benefits decisions or Medicaid EVV claims are implemented.

## Activation prerequisites

Use a NEW agency project in the organization selected by the account owner. Do not reuse the inactive nightclub or unrelated projects. No agency project has been created yet.

1. Apply `supabase/migrations/20261112142601_team_attendance.sql` through Supabase migrations. Keep `ath_private` out of exposed API schemas; keep public RLS enabled and all direct authenticated writes revoked.
2. Create the initial owner using Supabase Auth's managed account flow; seed `ath_staff` with that existing Auth user UUID, approved name, `role='owner'`, and `active=true`. Never put owner roles in editable user metadata. Disable public signups. Configure the agency's SMTP sender and login abuse protections before issuing invitations.
3. Configure the invitation template to link to `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=invite`. Allow only the exact production `/team/activate` redirect. Tokens are consumed on the server; successful activation removes them from the address. Password reset/self-service recovery is not implemented yet; an owner must handle recovery through Supabase Auth.
4. Set server-only production environment variables: `TEAM_SUPABASE_URL`, `TEAM_SUPABASE_PUBLISHABLE_KEY`, `TEAM_SUPABASE_SECRET_KEY`, `TEAM_PUBLIC_URL` (HTTPS origin with no trailing slash), and a strong `CRON_SECRET`. No secrets belong in client variables or source. Give previews separate synthetic infrastructure if real auth testing is needed. Production client data must not be connected to review previews.
5. For SMS, connect `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and either `TWILIO_MESSAGING_SERVICE_SID` or `TWILIO_FROM_NUMBER`. Enable the provider's opt-out processing and complete its sender registration. Record employee consent and valid international-format phone numbers before setting `REMINDERS_ENABLED=true` in PRODUCTION only. Previews never send invitations or SMS.
6. The cron runs daily at 12:00 UTC (6 AM Central Standard Time / 7 AM Central Daylight Time). Times in schedules are America/Chicago. Select a different daily trigger if the agency wants another time. Vercel plan limits and runtime duration must support the configured job. Each invocation works for up to 240 seconds and leaves excess jobs pending; large teams need a durable queue/repeated worker trigger before activation. Manager's manual action drains today's remaining pending jobs without resending accepted reminders.
7. Test an actual owner, manager and two employees on separate authenticated browsers; verify private photo access, logout, inactive accounts, assigned/unassigned homes, actual device GPS allowed/denied, overnight visits, photo upload, calendar edits, and end-to-end SMS with a consenting test phone. No real SMS or invitations were sent during development. Browser preview records are synthetic.

## Reliability and privacy

Clock timestamps come from the database. Clock events are idempotent and only one open visit per employee is allowed. Clock-out remains possible after an assignment is removed. GPS is requested only by a clock action with an acknowledgement; no continuous location polling. Accuracy over 100 meters, a reading older than two minutes, boundary uncertainty, outside-area and missing GPS are flagged; missing GPS never deletes time. Device GPS can be spoofed and does not prove continuous presence. Manager edits have protected before/after audit records.

Profile storage is a PRIVATE bucket. Signed URLs expire after 120 seconds; account access is checked by RLS. Uploaded JPEG/PNG/WebP files are decoded, resized and re-encoded with metadata removed. Photos are limited to 5 MB and 25 megapixels. No face recognition. Establish the agency's retention/deletion process and hosting/provider agreements before storing real client information; this implementation alone does not establish HIPAA or Medicaid EVV compliance.

Daily reminders contain employee-assigned client identifiers/names, times and addresses as requested. The agency should choose an approved client identifier if it wants to reduce SMS exposure on lock screens. Only current active opted-in employees with active assignments are queued. One outbox row per employee per day prevents duplicate daily sends. 'Accepted' means accepted by the SMS provider, NOT delivered. Ambiguous sends are flagged for provider review and never automatically retried. There is no delivery callback, change-notification SMS, reply/confirmation processing or automatic rescheduling. Late schedule changes require direct office follow-up.

Public inquiry flow prepares an email draft unless a real inquiry webhook is connected. A draft does not send or store an inquiry. `BOOKING_URL` must be a real HTTPS scheduler; Brittany opens an action card and cannot falsely confirm bookings. Coarse anonymous UI counts and connection timings go to hosting operational logs only; no visitor IDs, contact details or transcripts in measurement events. DNT/GPC disable these events. This is not a durable analytics dashboard.
